# Internationalization

ValoMapper uses `next-intl` without locale-prefixed routes. The locale comes from the `vm_locale` cookie, then `Accept-Language` on a first visit. Both resolve to one of the 18 locales supported by [valorant-api.com](https://valorant-api.com).

Arabic (`ar-AE`) is enabled with a best-effort RTL pass. The document `dir` comes from `LOCALE_META`; use logical Tailwind utilities (`ms-`, `me-`, `ps-`, `pe-`, `start-`, `end-`, `text-start`, `text-end`) for UI chrome. Spatial canvas/map content stays LTR, and legal documents stay LTR because the authoritative text is English.

## Key rules

- `src/i18n/messages/en-US.json` is the source of truth.
- Use semantic keys, not English sentences.
- Use ICU for plurals and interpolation.
- Never translate user content: strategy names, notes, canvas text, folder names.
- Stored and WebSocket-broadcast values stay canonical English (`AGENTS`, `MAP_OPTIONS`, ability names, etc.). Localize at render time only.
- Legal text stays English with a localized notice.

## Adding a string

1. Add the key to `src/i18n/messages/en-US.json` under the relevant namespace.
2. Use `useTranslations("<namespace>")` in client components, or `getTranslations` in server components.
3. Prefer `useFormatter()` for dates, numbers, and currency.
4. Run `npm run i18n:check`.

## Adding a locale

1. Add the locale code to `LOCALES` in `src/i18n/config.ts`.
2. Create `src/i18n/messages/<locale>.json` with the same key set as `en-US`.
3. Add the file to `MESSAGE_LOADERS` in `src/i18n/messages/index.ts`.
4. If the locale should be selectable, ensure it is not in `DEFERRED_LOCALES`.
5. Run `npm run i18n:check`.

Missing message files fall back to English so a locale can land incrementally.

## Valorant terms

Game terms are generated from valorant-api.com:

```bash
npm run build:valorant-i18n
```

This writes one file per locale to `src/lib/consts/data/valorant-i18n/`. The script fetches `agents`, `maps`, and `weapons` with `language=all` and maps:

- agents by English `displayName`
- abilities by agent + API `slot`
- maps by `maps.json` text to the API English name
- weapons by the local slug (with `knife` → API `Melee`)

Run it after a Valorant patch adds an agent, map, or weapon. Resolvers always fall back to the local English name.

`src/lib/i18n/valorant-terms.ts` holds the pure resolvers; `src/contexts/valorant-terms-context.tsx` exposes hooks for client components.

## Translation baseline

```bash
npm run i18n:translate
```

Generates machine-translated locale files from `en-US.json`. Values that come back empty fall back to English. ICU expressions are preserved verbatim, so plural branches inside them remain English until reviewed. Treat the output as a starting point, not a final translation.

## Validation

```bash
npm run i18n:check
```

Checks key parity against `en-US`, empty values, and placeholder parity. Run it in CI and before merging locale changes.

## Runtime

- Locale cookie: `vm_locale`, one year, `SameSite=Lax`.
- Switcher: `src/components/i18n/language-switcher.tsx`.
- Request config: `src/i18n/request.ts`.
- Server action: `src/i18n/actions.ts`.
- Root provider: `src/app/layout.tsx`.

`router.refresh()` applies a locale change without discarding client state. Routes are dynamic because the root layout reads cookies.
